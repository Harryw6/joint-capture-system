# Piper 手柄控制维修记录（软件误停已修，实机运动待恢复）

机械臂在 Home 后关节变硬，是电机使能后的保持力；无法继续用摇杆控制，需要结合实际反馈判断。本次没有恢复运动验收，不能称为机械臂已修好。

## 软件变更

- 同步机器人现有的关节遥操和 CAN 看门狗到两处仓库源码，避免后续部署旧版无保护发送器。
- 启动仅连接反馈接收线程，`piper_init=False`，不发送使能、回零或复位指令。
- Home 在确认遥操前检查原始反馈、机械臂状态和手柄中立；使能目标来自实际反馈，不使用固定安全位置。
- 界面分别显示六关节电机使能和手柄遥操状态，显示具体反馈错误；状态过期后不保留使能判断。
- 已知校准未通过时，`run/piper_calibration_required.json` 阻止 Home 和目标发送。只在厂家校准、实际姿态核对和反馈验证完成后由维护人员解除，随后重启遥操进程；不能仅删除标记作为修复。

软件保留每帧反馈新鲜度检查、断连与主循环超时保护、SDK 发送错误监测、2° 关节目标提前量和 1 mm 夹爪提前量。不允许末端模式、自动回零或点位回放。SDK 的接收端裁剪关闭以保留原始测量，发送目标由安全层逐次检查。

## 现场结果与限制

固件读回为 `S-V1.8-8`，CAN 和电机没有报告故障。固件限位 J2 为 0～180°、J3 为 −170～0°，与模型基本一致。最初原始反馈 J2 为 −2.494°、J3 为 +8.766°，夹爪为 −0.280 mm；盲目扩大限位或写入猜测的偏移不能解决姿态可信度问题。

用户明确确认稳固支撑、六关节对齐厂家零位及空夹爪完全合拢。关闭电机后观察到示教模式重新使能；切换待机并关闭电机后失能状态稳定。随后发送一次全关节零点配置，收到成功回执，但原始反馈没有通过零点验证。经用户单独授权复位一次，反馈变为 `[0, -2, 2, -102.5, -74.993, 0]` 度，J2/J3/J4/J5 仍超限。夹爪零点写入因关节验证失败而没有执行。该校准尝试未通过；此结果不能证明实际姿态已正确映射，也不能确定是固件或编码器故障。

最终六关节保持失能、主控无故障、遥操禁止发送，反馈接收进程正常运行。启动前后 CAN 发送计数均为 24；启动后的被动观察没有发现运动指令。保留已停止但待收尾的采集标记和原始数据。

## 后续软件修复与校准指引纠正

旧现场快照 `backups/raw-feedback-598094579008/snapshot.json` 记录了已使能后出现“发送失败：目标与实际位置偏差过大”，随后电子急停已确认。这个记录证明软件曾触发停止，不能把“Home 后有保持力、摇杆不响应”直接归因于硬件故障。

复现发现目标生成和发送检查使用不同反馈样本：目标在第一帧被限制到 2° 提前量，第二帧仅反向变化 0.001°，旧发送器就误判超差并急停。修复把目标增量计算移入发送事务，用同一份新鲜反馈计算和检查；保留目标先相对于原生成样本的校验，以拦住损坏或人为改写的目标。关节 2°、夹爪 1 mm 的提前量、原始反馈检查、失联保护和急停行为均保留。CSV 和快照在发送事务后重新取目标状态。

机器人实际 Python 3.8、pygame 和 cuRobo 环境进行了完整控制循环模拟：Home 使能模拟机械臂后，左摇杆 J1/J2、右摇杆 J3/J6、方向键 J4/J5 均持续改变对应目标，共生成 302 次模拟关节指令，最大单次控制处理时间 6.414 ms，没有误急停。模拟对象没有创建真实 CAN 接口，此结果不代表实机运动验收。

厂家最新常规校准视频在约 0:43 明确要求 J4 转到右侧限位、J5 向上抬到限位。安装的厂家 SDK 校准示例也指定 J4 顺时针到限位、J5 上抬到限位。上次将 J4/J5 的零位标记姿态当作校准姿态的指引不准确；已经写入的控制器基准不能通过恢复 Python 源码撤销。仅收到成功回执也不足以验证姿态映射。参考：[厂家校准视频与固件说明](https://agilexsupport.yuque.com/staff-hso6mo/ihw47g/svzsuopxhgd4n8w5#C1CUp)、[SDK 校准示例](https://github.com/agilexrobotics/piper_sdk/blob/master/piper_sdk/demo/V2/piper_set_joint_zero_cpv.py)。未执行 CPV 校准、重复置零或第二次主控复位。

用户希望先不再校准，因此本次只部署两处软件修复，重启反馈接收进程，保持校准保护。部署后六电机仍失能，`command_sent=false`，反馈快照持续更新，CAN 发送计数仍为 24。两文件部署前备份在 `backups/teleop-stick-fix-20261010/`。不能仅删除校准保护或写入猜测的软件偏移来宣布手柄控制已恢复；仍需纠正姿态基准并完成现场动作验证。

本次相关离线测试 54 项通过（控制与保护 41 项，采集转换回归 13 项），包含反馈样本切换时的关节及夹爪边界、全部六关节方向输入、无摇杆输入时异常漂移、非法目标和既有失联／急停保护。

参考：[SDK 接口说明](https://github.com/agilexrobotics/piper_sdk/blob/master/asserts/V2/INTERFACE_V2.MD)、[厂家提供的零点视频入口](https://github.com/agilexrobotics/piper_sdk/issues/128)。厂家对另一例夹爪负读数建议使用上位机处理；不能据此认定本机适用同一硬件操作。
