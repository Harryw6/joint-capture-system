# 连续采集中的任务打点

先启动一条采集，等数据持续写入，再使用“任务打点”区。录制过程中可以
反复点击“任务开始”和“任务结束”，无需停止录制或重新初始化设备。
这两个按钮只记录时间，不会开始/停止录制，也不会改变机械臂状态。

- 任务开始：打开下一段，保存当前本机时间。
- 任务结束：关闭当前段，保存结束时间与时长。
- 重置本段开始：尝试不成功时，将当前未结束段的开始改成现在；旧开始点
  保存在重置历史和事件日志里，已结束段保持原样。

未确认采集启动成功、数据写入停滞或状态失联时，不能开始或重置新的一段。
已打开段仍可结束，但会标为“待核对”。采集 ID 改变后，旧页面的操作会被
拒绝，不会写到新的数据目录。刷新页面和重启控制台后，记录仍保留。

每个点击保存 HTTP 请求到达本机服务时的纳秒 wall/monotonic 时间，以及
浏览器点击的毫秒时间供核对。精度字段不等于人工打点或相机曝光准确度。
任务闭合时优先用单调时钟计算时长；本机系统时钟跳变或控制台重启跨越
一个任务段时，会保存原始时间并标记待核对。

本机先同步落盘到 `<manifest_root>/task_markers/<capture_key>/`，包括：

- `events.jsonl`：追加式、已同步落盘的原始操作日志。
- `task_segments.json`：当前段、已结束段和重置历史。
- `task_segments.csv`：便于后续筛选和切分的区间表。
- `task_clock_samples.jsonl`：后台测得的本机/机器人时钟探测样本。

这些小文件会后台复制到实际采集目录的 `annotations/task_markers/`，并同步
落盘、回读比较。暂时无法连接时，本机记录不会丢失；页面显示同步失败并
重试。每次打点后的探测样本保留两端时间和 RTT；可以使用它恢复本机打点
时间到机器人原始数据时间的映射。时钟映射不可用时会单独显示待补齐。

“自动识别”支持当前只有 Unitree 录制、控制台保留旧联合任务的情况。
联合任务的一端失联时，已有任务段仍绑定原联合任务，不自动降级到单机。
需要明确选择范围时可使用“仅 Unitree”或“联合采集”。

“已结束”和“已同步”分别表示时间点配对和标注文件复制完成，不表示原始
图像、机器人状态或双机时间对齐已通过完整性验收。
