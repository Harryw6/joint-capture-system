# Fast stop and deferred post-processing

The operator needs the next joint episode to start soon after pressing Stop. Stopping must first durably record the requested desktop T1, stop both owned recorders, and preserve their raw data and remote paths. A successful fast stop means both recorders are idle and the clock monitor has closed; it does **not** mean data quality has passed.

P450 `stop-fast` stops rosbag and releases the capture marker, leaving rosbag recovery and joint alignment inspection for `finalize-raw SESSION_DIR`. MP4/video export remains a separate, manual `export SESSION_DIR` command and is never run by Stop or "处理待办". Unitree `stop` terminates its owned recorder/gamepad/bridge, writes stop metadata, releases the active marker, and leaves raw files untouched; `finalize EPISODE_DIR` runs the existing validator and writes its report/manifest. The desktop `stop` records `postprocess=pending` atomically with the completed episode. A separate, repeatable `finalize` desktop operation runs remote raw finalizers then joint alignment inspection, recording success or failure per episode. Only idle devices may run finalization, and failed finalization remains retryable. No raw data is deleted or transferred during stop.

The console labels fast stop as "录制已停止，待后处理" rather than "验收通过", shows pending work, and exposes an explicit "处理待办" action. The action picks the oldest pending/failed completed episode when devices are idle. This avoids CPU-heavy inspection and verification competing with the next capture. A subsequent start does not depend on previous post-processing success, but still requires both devices idle and a fresh clock preflight. The historical 2026-09-23 partial episode is not silently converted; it requires separate recovery and data review.

Safety: no change to flight arming, arm enable, HOME behavior, or recorder ownership checks. If either fast stop fails or remote status is uncertain, the active pointer remains and the console does not offer Start. Closing the page never runs finalization implicitly.
