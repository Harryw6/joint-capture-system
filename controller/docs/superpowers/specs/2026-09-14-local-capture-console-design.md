# P450 / Unitree 本机采集控制台设计

日期：2026-09-14。状态：待用户审阅。本文是设计，不表示界面已实现。

## 1. 目标及方案选择

用户在当前 Windows 电脑双击桌面入口打开网页，自主控制联合采集开始和停止，查看两台设备的实际采集状态、数据路径、内存及磁盘空间，并在停止后得到对时和数据验收结果。

采用本机网页加独立 Python 后台，复用已经实测通过的 jointctl 与远端命令。相比仅使用批处理，网页能持续呈现状态；相比原生桌面应用，网页无需增加另一套 GUI 运行时。后台仅监听 127.0.0.1，不发布到互联网或局域网。网页及样式全部随安装包提供，不依赖 CDN 或外网。

沿用当前 Python 标准库和 Windows OpenSSH。第一版用 HTML/CSS/JavaScript 和本地 HTTP API；不引入 React、Node 构建工具或远端代理服务。界面使用中文，面向桌面浏览器。

## 2. 组件与责任

- 新增本机服务模块：提供静态页面、状态缓存、异步操作队列和有限的控制 API。
- 操作执行器：使用固定 Python 可执行文件、固定配置路径及参数数组运行现有 jointctl start/stop/recover/align 子进程；不经 shell 拼接用户输入。停止保留现有自动验收逻辑。
- 状态采样器：调用现有状态适配器，读取 manifest 和 alignment.json，采样与长时间的启动、停止、导出任务独立。
- 资源采样器：通过 SSH 只读读取 Linux /proc/meminfo 和数据所在文件系统容量。对两台分别设置超时，不要求 sudo，不修改配置。
- 网页：只显示快照和提交操作，不负责采集生命周期、对时计算或决定会话归属。

沿用 D:\OneDriveData\Desktop\joint_manifests。原始 rosbag、PKL、CSV 留在远端，不因使用界面而自动下载或删除。

## 3. 操作与状态

桌面新增 JointConsole.bat。它启动隐藏的独立后台进程并打开浏览器；若服务已运行则复用该实例。服务启动本身不得启动采集。重复启动入口不得创建第二个控制服务。

开始：填写采集说明及任务名，检查两端连接和现有会话归属，提交开始任务，显示准备进度。只有现有控制器完成双方就绪与时钟质量门槛后，才显示联合采集中及共同 T0。

停止：立即提交停止任务，由现有控制器记录共同 T1，然后停止、导出及验收。界面分别显示停止录制、保存/导出、校验中、通过或未通过。不能把任务已受理或 manifest complete 当成数据验收通过。

操作以异步任务 ID 返回，页面请求不等到 SSH 操作完成。控制任务与真实采集状态分开显示。错误展示设备、阶段、简明原因和重试入口；详细日志可展开。停止失败时保留 active 和首次 T1，重试不得变更边界或新建 episode。

网页和现有 CLI/批处理共用跨进程变更操作锁，防止两个页面或命令行并发启停。锁只约束 start/stop/recover 等变更，不能阻塞状态读取；进程崩溃后锁可安全释放。启动子进程存活时明确显示“准备中，请等待”，不提供伪装有效的取消按钮。若准备失败按现有回滚逻辑处理。

网页刷新、关闭不结束采集；后台及任务子进程独立存活。页面重新连接后从服务状态和 manifest 恢复。后台意外退出或电脑重启不承诺远端自动停止，也不自动重复执行未确认操作；重新打开先核对远端、提示恢复。未知/外来会话绝不自动停止。保留原桌面批处理作为备用入口。

## 4. 界面内容

顶部为总状态、episode ID、任务名称、共同区间计时，以及开始、停止并校验两个主要按钮。计时基于共同 T0，不使用点击按钮时间。按钮状态由后台允许的操作决定，同时在服务器端再次校验。

中间并列 P450 与 Unitree 状态卡，各显示：

- 连接、采集及保存状态；最后成功采样时间和信息是否过期。
- 本次实际远端完整路径及复制按钮。路径未返回时显示“尚未取得”，不猜测；历史路径明确标为上次采集。
- P450 已写入字节；Unitree 保存帧数、丢弃数、保存错误。无法从现有状态取得的字段显示未知，不编造 0。
- 整机 RAM 已用/总量、占比和可用量；已用定义为 MemTotal-MemAvailable，单位 GiB，不与单个录制进程占用混淆。
- 数据所在文件系统的可用/总空间和占比，默认低于 10 GiB 警告，阈值可配置；不因监控取值失败触发停止。

底部显示时钟探测健康、样本更新时间、模型误差估计及异常原因；停止后展示共同有效区间、校验结果、告警、两端路径和本机报告路径。没有有效区间时明确显示未通过，不将 coverage_interval 当成通过结果。

主机资源及采集状态目标每 2 秒更新一次，网页每秒读取后台缓存。每台最多一个同类探测在途，慢响应不排队堆积，超时后退避重试。超过 6 秒无成功更新标为过期；失联显示未知并保留带时间的最后值。失联不能显示空闲或正常采集中。监控不得阻塞更高优先级的停止命令。

## 5. 对时与安全边界

不调整任一系统时钟、不要求 P450 联网、不改变当前数据时间映射方法。共同 [T0,T1) 定义不变，原始数据包含首尾冗余。模型毫秒估计明确标为估计，不能宣传为同时曝光或硬件同步。

Unix 纳秒时间戳通过 API 作为十进制字符串传输，避免 JavaScript Number 超过安全整数范围损失精度。时长由后台以秒/毫秒单独输出，页面不重新计算精密时钟模型。

HTTP 变更请求只接受 POST 和受限 JSON 字段，校验本机 Host、同源 Origin 及服务生成的操作令牌；不开放 CORS、不暴露任意 shell、任意文件读取或下载接口。静态资源只允许包内白名单文件。远端 SSH 密钥/密码不返回浏览器、不存入页面或日志，保持既有认证方式。

## 6. 第一版明确不做

- 实时视频预览、Unitree MP4 转换、共同区间视频裁剪。
- 从手机/其他电脑访问、多用户、云托管。
- 机器人运动、解锁、使能、CAN 自动配置或系统校时。
- 自动联停看门狗、自动故障注入和长时间采集保证。

P450 原脚本 30 分钟限制仍在。界面固定显示限制和提前停止提示；以本次 P450 start 请求发出时间计算保守参考剩余时间，并明确实际限制由远端脚本决定。没有该证据时仅显示限制，不展示虚假的精准倒计时。实际自动联停保护另立需求，不把状态监控描述成已具备看门狗。

## 7. 安装及验收

扩展现有安装器，打包网页资产和启动入口，安装前备份旧程序，不覆盖历史 manifest 或远端数据。现有命令行行为保持兼容；新增跨进程锁需单独回归验证。

验收包括：

1. 无真机测试状态接口、资源解析、输入验证、纳秒精度、重复点击/跨入口互斥、超时与过期、异步任务恢复及报告状态区分。
2. 浏览器实测按钮、长路径显示及复制、错误提示、刷新重连、键盘可操作性；先在模拟后端测试，避免 UI 检查误启动真机。
3. 已有 188 项回归继续通过；安装后检查源码及资源一致性。
4. 在用户授权和两端空闲前提下，实机短采集验证网页开始、数据增长、RAM/磁盘显示、网页刷新、停止、自动验收、路径和最终 idle。任何失败优先安全清理本次所属会话。
