# Piper 采集遥操安全修复

## 修复范围

入口为 `remote/unitree/piper_gamepad_teleop.py`，由采集界面初始化设备时启动。
`safe_teleop.py` 使用实际关节反馈约束目标；`piper_safety.py` 负责 SDK 错误检测、逐路反馈超时和循环看门狗。
这三个文件与 `robots/unitree/home/unitree/heterovla-collection/onboard/` 下的对应文件保持一致。
直接运行第三方 `Gamepad_PiPER/main.py` 会绕过这些保护，不能用于此次验收。旧推理控制入口也不在此次修改范围内。

## 行为

- 初始化不使能，不发送运动目标。所有摇杆、方向键和扳机中立后，按 Home 显式确认。
- 使能前必须收到新鲜状态、三组关节、夹爪及六个驱动的反馈。先用实测姿态覆盖旧目标，再尝试使能；最多等待 3 秒，逐轮处理输入，不阻塞等待。
- 关节目标每秒增加速度为 20° × 摇杆倍率 × 输入幅度；默认倍率 0.5，即满杆目标速率 10°/s。单次积分时间不超过 20 ms，不补算卡顿期间的位移。
- 目标相对实测关节角的领先/落后范围不超过 2°。释放或反向操作某一轴时，丢弃该轴积累的目标，从当前反馈重新计算；静止后保留固定保持目标，不持续追随位置漂移。
- 夹爪沿用左扳机闭合、右扳机打开；取消原先的端点跳变。目标速率最大 10 mm/s，目标与反馈距离不超过 1 mm；松开或反向时丢弃积累。
- Home 在遥操中请求快速停止，不回零、不自动复位。回零、已存点位回放、笛卡尔模式和 MIT 快捷切换禁用，LB/RB 的原有短按/长按速度调节保留。
- 断连、无效输入、任意必需反馈超过 250 ms 未更新、循环超过 250 ms 未完成输入处理、驱动失使能、状态报错和检测到 SDK/CAN 错误都会锁定遥操并请求停止。
- 异常停止使用现场 SDK 0.6.1 的 `MotionCtrl_1(0x01, 0, 0)`。最多尝试三次，间隔至少 50 ms；不会发送 `0x02` 自动恢复，不会自动回零或关使能。
- SIGINT/SIGTERM 阻止后续普通命令，异常退出与写盘错误均执行停止清理。普通录制“停止并保存”依旧只停止录制；不改变常驻遥操的既有生命周期。
- 重连不会解除锁定。先现场排除故障并解除硬件急停，然后释放全部操作件、重新按 Home，从新鲜实测姿态恢复。

## 状态与 SDK 兼容性

现场 SDK 源码与已安装文件哈希一致：
`2d4fdcd65cedfcfcc0c7347feba1f693c28ab4a7b27c66f9dfca931fc407d7dc`。
其发送方法常返回 None，失败写入 SDK logger。因此不能把返回 None 当作硬件成功确认；本实现同时检查异常、显式 False 和 SDK ERROR 日志。
`command_sent` 仅表示这一轮提交过程中未检测到 SDK 发送错误，不表示运动已经完成。

SDK 的关节集合时间戳会被任意一组关节刷新。接收适配器分别检查 0x2A5/0x2A6/0x2A7，避免单组更新掩盖其他组断流；同时检查状态 0x2A1、夹爪 0x2A8、驱动 0x261–0x266。
界面显示 `stop_requested`、`stop_confirmed` 和 `stop_error`。`stop_confirmed` 仅表示收到新鲜的机械臂急停状态，不等于通过外部传感器证实全部机械运动为零。

## 验证与限制

离线测试使用虚拟输入、反馈、时钟和 SDK；覆盖六轴持续输入 5 秒、释放/反向、夹爪、逐路丢帧、断连重连、日志/返回值/异常形式的发送失败、Home、使能超时、独立线程超时、SIGTERM、输入异常、写盘异常、镜像一致性与界面状态过期。

2026-09-30 完整 controller 测试结果：415 passed、2 skipped，35.40 秒。跳过项为未安装 Chrome 的浏览器测试；界面 JavaScript 另外通过 Node 语法检查。Python 模块编译检查通过。SDK、机械臂、手柄和 GPU 均未在测试中连接或使能；没有做物理运动验收。

安装工具 `controller/scripts/install_piper_safety.py` 只安装上述三个 onboard 文件，默认仅检查；`--apply` 才写入。它获取采集操作锁、拒绝存活的采集/遥操进程、核对现场旧版哈希与发布包哈希、先备份后原子替换，并在中途失败时恢复已替换文件。旧录制指针仅保留，不替用户删除或恢复数据。工具不会启动或重启任何服务，也不会发送机器人命令。Windows 界面三个变更文件需在关闭控制台后独立备份和更新。

2°、1 mm、250 ms 和速度上限是保守的初始验收参数，不是针对负载、姿态和机械限位认证的安全距离或停止时间。松手保持使用新鲜位置反馈作为新目标，其制动效果必须在实机低速验证。
Python 看门狗依赖进程、线程调度和可用 CAN；进程被强杀、整机卡死、SDK 调用永久阻塞、物理断网/CAN 断线时，软件不能保证停止命令到达。SDL 未报告断连却持续返回冻结的轴值时，也不能仅凭成功轮询断定输入来自新的无线数据包。必须保留实体急停和操作者看护，不能宣称本修复替代硬件安全链。

实机验收需由操作者现场进行：先核对手柄中立映射和实体急停；低速逐关节短推、松手、反向，再逐渐延长输入；检查反馈及目标差值和停止状态。不要直接用长按大幅运动进行首次验收。本次自动化不启动遥操，不发送运动、使能或复位指令。
